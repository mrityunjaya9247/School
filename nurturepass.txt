NurturePass
Web App UI / UX Screen-by-Screen Build Specification
Build guide for a multi-tenant RFID attendance, school-safety, parent-communication and AI-assisted care platform in React + PostgreSQL.
Screens
30 buildable pages
Components
50+ reusable units
Personas
Principal, teacher, gate, admin
Implementation
React + PostgreSQL + edge agent
How to work through the document
Start with the app shell, tenant login, design tokens and permission model; then follow screen numbers in build order.
Each screen includes a visual wireframe, core components, data/API needs, exception states and definition of done.
AI screens are intentionally human-in-the-loop: explainable, role-aware, editable and never autonomous.
1. Experience foundation and build rules
Product promise
Every entry recorded. Every child cared for.
Experience tone
Calm, warm, reliable and school-first.
Security model
school_id tenancy + role claims + DB row-level security.
Core journeys
Arrival
Tag read → direction classifies entry → attendance updates → parent notification follows consent → dashboards refresh.
Exit
Antenna sequence confirms exit → exit event stored → parent alert sent → no entry/exit ambiguity hidden from operators.
Care Loop
Attendance pattern → evidence shown → teacher adds context → editable parent note draft → human review → send.
Operations
Reader heartbeat/read quality → device alert → operator diagnoses safely → exception/ticket/audit trail.
AI
Scoped aggregates + approved evidence → insight/draft → teacher/principal reviews → action is only human initiated.
Non-negotiables
No continuous tracking: use only defined school checkpoints.
No automatic child safety, wellbeing or attendance decisions.
No parent message is sent through a channel without recorded consent.
Manual corrections never overwrite source RFID events; they create auditable correction records.
Teachers see only their assigned classes; gate operators see only data needed to solve gates/tags.

Guardrails to implement before AI goes live
Show evidence and a concise “why surfaced” explanation for every AI insight.
Never use AI to label children, infer a diagnosis, approve exit, decide safety status or auto-send communications.
Run AI queries through the same tenant/role filters as standard APIs.
Retain a minimal audit record: action type, source IDs, user decision and feedback; avoid storing unnecessary raw prompts.
Provide a “Not helpful / Incorrect evidence” feedback path and an administrative kill switch for every rule/feature.
